# SoulMD Hub: RESTful API Reference Specification

## 1. Global Specifications

### 1.1. Base URL
All headless API endpoints are rooted under the following standard path structure:
```http
https://<your-production-domain>/api

```

### 1.2. HTTP Headers

Unless otherwise explicitly stated, every request interacting with the platform routing mesh must supply the following core headers:

* `Content-Type: application/json; charset=utf-8`
* `Authorization: Bearer <your_32_byte_secret_api_key>` (For Headless API access)
* `X-CSRF-Token: <token>` (Required exclusively for internal state-changing browser sessions)

## 2. Authentication & Account Mesh

### 2.1. Register User

Creates a new platform creator account and issues a distinct cryptographic token.

* **Method / Route:** `POST /register`
* **Authentication:** `None (Public)`
* **Request Body:**
```json
{
  "username": "developer101",
  "password": "securepassword123",
  "email": "dev@example.com"
}
|-- Key Parameters --|
* username: String (3-50 chars, alphanumeric, underscores, hyphens only).
* password: String (Min 6 chars).
* email: String (Valid email formatting constraints).

```


* **Success Response (201 Created):**
```json
{
  "success": true,
  "message": "Account created successfully",
  "api_key": "7f8a9b2c3d4e5f6a7b8c9d0e1f2a3b4c..."
}

```



### 2.2. Login User (Web2 Password Channel)

Authenticates a user via classical password exchange.

* **Method / Route:** `POST /login`
* **Authentication:** `None (Public)`
* **Request Body:**
```json
{
  "username": "developer101",
  "password": "securepassword123",
  "remember": true
}

```


* **Success Response (200 OK):**
```json
{
  "success": true,
  "message": "Login successful",
  "api_key": "7f8a9b2c3d4e5f6a7b8c9d0e1f2a3b4c..."
}

```



### 2.3. Web3 Wallet Login (Silent Signature Authentication)

Performs automated silent login validation via cryptographically verified key ownership.

* **Method / Route:** `POST /wallet-login`
* **Authentication:** `None (Public)`
* **Request Body:**
```json
{
  "account_id": "yanshekki.near",
  "public_key": "ed25519:G1p9XJv8m...",
  "signature": "L/xN7f8a9b2c3d4e5f6a7b8c9d...",
  "message": "soulmd_auth:1716330000000"
}
|-- Key Parameters --|
* account_id: Explicit NEAR Protocol wallet address.
* public_key: Full Ed25519 public key identifier prefix included.
* signature: Base64-encoded detached signature generated by frontend LocalStorage keypair.
* message: The exact "soulmd_auth:<timestamp_ms>" challenge string.

```


* **Success Response (200 OK):**
```json
{
  "success": true
}

```


* **Error Response (401 Unauthorized):**
```json
{
  "success": false,
  "error": "Security validation failed"
}

```



### 2.4. Bind Web3 Wallet

Permanently locks a Web3 wallet address to an existing Web2 session account.

* **Method / Route:** `POST /bind-wallet`
* **Authentication:** `Bearer Token or Session Cookie`
* **Request Body:**
```json
{
  "action": "bind",
  "wallet": "yanshekki.near",
  "public_key": "ed25519:G1p9XJv8m...",
  "signature": "L/xN7f8a9b2c3d4e5f6a7b8c9d...",
  "message": "soulmd_auth:1716330000000"
}

```


* **Success Response (200 OK):**
```json
{
  "success": true,
  "message": "Wallet bound successfully!"
}

```


* **Error Response (409 Conflict - Anti-Twin Intercept):**
```json
{
  "success": false,
  "error": "Action Blocked: This wallet address is already bound to another SoulMD Hub account!"
}

```

## 3. Chat Interaction & Multiplayer Sync Engine

### 3.1. Fetch Conversation Logs

Retrieves the contextual message history logs linked to a active session.

* **Method / Route:** `GET /chat`
* **Authentication:** `Bearer Token or Session Cookie`
* **Query Parameters:**
* `soul_id`: Integer (The designated AI Agent ID).
* `session_token`: String (`^[a-zA-Z0-9_-]{8,128}$`).


* **Success Response (200 OK):**
```json
{
  "success": true,
  "messages": [
    {
      "role": "user",
      "sender_name": "developer101",
      "content": "Initialize trace analysis loop."
    },
    {
      "role": "assistant",
      "sender_name": "AI Assistant",
      "content": "Trace sequence engaged. Awaiting constraints."
    }
  ]
}

```



### 3.2. Post Chat Message (Official Engine Gateway)

Submits a instruction turn to the central platform gateway. Subject to account limits.

* **Method / Route:** `POST /chat`
* **Authentication:** `Bearer Token or Session Cookie`
* **Request Body:**
```json
{
  "soul_id": 1,
  "session_token": "multiplayer_session_999",
  "content": "Verify compiling structures against the attached document screenshot.",
  "image": "data:image/jpeg;base64,/9j/4AAQSkZJRg...",
  "is_private": false
}
|-- Key Parameters --|
* image: Optional Base64 data string. Triggers Together AI Multimodal processing if active.
* is_private: Boolean flag. Toggles multi-tenant shielding.

```


* **Success Response (200 OK):**
```json
{
  "success": true,
  "reply": "Compiling structures evaluated. Zero legacy layout anomalies detected.",
  "sender_name": "AI Assistant",
  "truncated": false,
  "needs_upgrade": false,
  "finish_reason": "stop"
}

```

When the model stops early because the tier `max_tokens` cap was hit, `finish_reason` is `length` (or `max_tokens`), `truncated` is `true`, and `needs_upgrade` is `true` for Free/VIP so the client can prompt an upgrade. PRO keeps `needs_upgrade: false` (highest platform output cap).

### 3.3. Post Chat Message (BYOK Proxy Gateway)

Executes inference on user-provided compute matrices. Free of platform turn deductions.

* **Method / Route:** `POST /self-chat`
* **Authentication:** `Session Cookie Required`
* **Request Body:** *(Identical mapping layout as standard `POST /chat`)*
* **Success Response (200 OK):**
```json
{
  "success": true,
  "reply": "Inference generated utilizing custom BYOK cluster keys.",
  "sender_name": "AI Assistant",
  "truncated": false,
  "needs_upgrade": false,
  "finish_reason": "stop"
}

```

BYOK may still set `truncated: true` if the proxy `max_tokens` is reached; `needs_upgrade` stays `false` (custom key, not a platform tier limit).



### 3.4. Real-Time Multiplayer Sync & Presence Heartbeat

Volatile high-frequency endpoint providing atomic differential syncing and connection status tracking.

* **Method / Route:** `GET /chat-sync`
* **Authentication:** `Session Cookie or Guest Session`
* **Query Parameters:**
* `soul_id`: Integer (AI Agent target).
* `session_token`: String (Target thread identifier).
* `last_id`: Integer (The current highest Message ID successfully compiled locally by the client interface).


* **Success Response (200 OK):**
```json
{
  "success": true,
  "online_count": 3,
  "new_messages": [
    {
      "id": 412,
      "role": "user",
      "sender_name": "Anonymous #F8B3",
      "content": "Is anyone else monitoring this trace loop?"
    }
  ]
}

```

## 5. Mini Apps

Form-driven tools backed by curated SOUL personas (or builtin prompts). Shares the same platform tier quotas as chat (`daily_limit`, `max_input`, `max_tokens`). Does **not** return soul source content.

### 5.1. List / Describe Mini Apps

* **Method / Route:** `GET /apps`
* **Authentication:** None (public)
* **Query params:**
  * `category` (optional): `destiny` | `life` | `emotion`
  * `q` (optional): free-text search over title/description/slug
  * `slug` (optional): when set, returns a single app detail with form `fields` schema instead of the list

* **List Success Response (200 OK):**
```json
{
  "success": true,
  "count": 1,
  "data": [
    {
      "slug": "name-advisor",
      "icon": "fa-signature",
      "category": "destiny",
      "title": "Name Advisor",
      "description": "…",
      "badge": "popular",
      "field_count": 5,
      "soul_configured": true
    }
  ]
}
```

* **Detail Success Response (200 OK):**
```json
{
  "success": true,
  "data": {
    "slug": "name-advisor",
    "icon": "fa-signature",
    "category": "destiny",
    "title": "Name Advisor",
    "description": "…",
    "fields": [
      {
        "name": "surname",
        "type": "text",
        "label": "Surname",
        "placeholder": "e.g. Chen",
        "required": true,
        "maxlength": 20
      }
    ],
    "soul_configured": true,
    "has_builtin_prompt": true
  }
}
```

### 5.2. Run Mini App

* **Method / Route:** `POST /apps`
* **Authentication:** Session cookie (+ `X-CSRF-Token`) **or** `Authorization: Bearer` (VIP/PRO for API keys; Free keys rejected)
* **Request Body:**
```json
{
  "slug": "name-advisor",
  "fields": {
    "surname": "Chen",
    "gender": "female",
    "birth_datetime": "1989-09-01 06:00",
    "preferences": "gentle, wood/fire",
    "count": "3"
  }
}
```

* **Success Response (200 OK):**
```json
{
  "success": true,
  "reply": "Here are three name options…",
  "sender_name": "AI Assistant",
  "truncated": false,
  "needs_upgrade": false,
  "finish_reason": "stop",
  "session_token": "app_name-advisor_ab12cd…",
  "slug": "name-advisor"
}
```

When the model hits the tier `max_tokens` cap, `truncated` is `true` and Free/VIP receive `needs_upgrade: true`.

* **Error cases:** missing/invalid fields (400), daily limit (403 + `needs_upgrade`), Free API key (403 + `needs_upgrade`), input over tier char limit (400), app not found (404).

* **Soul binding:** `MINI_APP_SOUL_MAP` in `config.php` maps slug → public non-NFT `soul_id`. Apps **without** a positive mapped id are **hidden** from list/detail and cannot be run (404).

```json
{
  "success": false,
  "error": "You have reached the free preview capacity of 10 messages. Upgrade to unlock completely unlimited conversations.",
  "needs_upgrade": true
}

```

```json
{
  "success": true,

}

```
